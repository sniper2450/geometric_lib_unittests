## Написание Unit-тестов.

### 1. Цели и задачи тестирования
* **Цель:** Проверка корректности, надежности и стабильности работы программных модулей вычисления геометрических параметров (`circle.py`, `square.py`, `rectangle.py`, `triangle.py`).
* **Задачи:**
  * Реализация автоматизированных unit-тестов с помощью встроенного фреймворка `unittest`.
  * Проверка функций на корректных (позитивных) наборах данных.
  * Проверка поведения модулей при передаче некорректных типов данных (строк) и граничных условий.
  * Проверка устойчивости алгоритмов при работе с некорректными значениями (отрицательными числами).

### 2. Описание тестируемого продукта
Тестируемый продукт представляет собой набор из четырех независимых математических модулей на языке Python:
* **`circle.py`**: вычисление площади круга и длины окружности по радиусу r.
* **`square.py`**: вычисление площади и периметра квадрата по стороне a.
* **`rectangle.py`**: вычисление площади и периметра прямоугольника по сторонам a и b.
* **`triangle.py`**: вычисление площади по основанию a и высоте h, а также периметра по трем сторонам a, b, c.

### 3. Область тестирования
**В области тестирования находятся:**
* Корректность работы формул при валидных целых и вещественных числах (включая нулевые значения).
* Реакция функций на ошибочные типы входных данных (вызов исключения `TypeError`).
* Реакция функций на логически невозможные геометрические параметры (вызов исключения `ValueError` для отрицательных чисел).

**Вне области тестирования:**
* Производительность алгоритмов при вычислениях с экстремально большим значениями (Stress testing).
* Поведение интерфейса командной строки и интеграция модулей друг с другом.

### 4. Стратегия тестирования
* **Уровень тестирования:** Модульное (Unit) тестирование.
* **Подход:** Метод «черного ящика» (Black Box). Тесты проверяют только контракт функции: соответствие выходного значения заданным входным параметрам без изменения исходного кода.
* **Техники тестирования:**
  * Эквивалентное разделение (позитивные сценарии, некорректные типы, недопустимые значения).
  * Анализ граничных значений (тестирование нуля).
* **Инструмент автоматизации:** Стандартная библиотека Python `unittest`.

### 5. Критерии приемки
Для успешного прохождения контроля качества код должен отвечать следующим критериям:
1. Все тесты на позитивные сценарии и валидные типы данных завершаются успешно (`OK`).
2. При передаче некорректных типов данных (строк) или геометрически невозможных параметров (отрицательных чисел) программные модули должны блокировать выполнение математических операций и выбрасывать соответствующие типы исключений (`TypeError` и `ValueError`).

### 6. Ожидаемые результаты и анализ дефектов
При запуске тестов командой `python -m unittest discover` фреймворк возвращает общий статус **`FAILED`** с указанием на проваленные проверки (`failures`). 

Данный результат является **ожидаемым и корректным**, так как тесты успешно выявили критические дефекты (баги) в исходных геометрических модулях, которые не содержат внутренней валидации параметров:

| Модуль | Тестовый сценарий | Входные данные | Ожидаемое поведение (Тест) | Фактическое поведение кода | Статус теста |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`circle.py`** | Отрицательный радиус | `area(-3)` | Ошибка `ValueError` | Возвращает положительное число (из-за r²) | **FAIL** |
| **`square.py`** | Передача строки в периметр | `perimeter("A")` | Ошибка `TypeError` | Происходит дублирование строки: возвращает `"AAAA"` | **FAIL** |
| **`rectangle.py`** | Умножение строки на число | `area("A", 3)` | Ошибка `TypeError` | Возвращает размноженную строку `"AAA"` | **FAIL** |
| **`rectangle.py`** | Отрицательные стороны | `area(-5, 10)` | Ошибка `ValueError` | Рассчитывает отрицательную площадь `-50` | **FAIL** |
| **`triangle.py`** | Отрицательные стороны | `perimeter(-3, 4, 5)` | Ошибка `ValueError` | Складывает числа и возвращает неверный периметр `6` | **FAIL** |

**Заключение тестирования:** Разработанный комплект unit-тестов полностью выполнил свои задачи: зафиксировал работоспособность корректных математических сценариев и наглядно продемонстрировал слабые места в стабильности кода при столкновении с некорректными входными данными. Тестируемый продукт требует доработки (внедрения блоков `try-except` или операторов `if-raise`).
